# 主动接话（设计稿，未实现）

问题：有人 @ 了机器人之后，接着聊的时候常常不再 @；别人想加入话题也不会 @；主播也会说起机器人（「你可以跟他说话」「给它开个会员」）。现在这些机器人都听不到。可每条弹幕、每句主播的话都交给 Claude 又太贵。

## 方案

每 20 秒，只要有新的观众弹幕或主播说的话（唱歌不算），就把它们连同之前的 25 行交给一个便宜的模型判断：有没有人在跟机器人说话、说到机器人、或在接机器人的话。要回的话，交给现有的回复流程（同样的人设和上下文）回一句。

1. **不做关键词预过滤**。大家说起机器人时常常不提名字，只说「它」「他」「小咪」「群聊小助手」，规则抓不到，要结合上下文判断。
2. **判断模型**：Codex 的 `gpt-6-luna`，medium 强度，不联网，用 `--output-schema` 要求 JSON：

   ```json
   { "reply": true, "to": "昵称或主播", "line": "那一条的原文", "why": "一句话理由" }
   ```

3. **校验**：`line` 必须是这一批新内容里的一条，否则丢弃（试的时候它选过一条礼物提示）。已经 @ 了机器人的不管，那些照常处理。
4. **限频**：主动回复每 2 分钟最多 1 条；冷却期间不调用判断模型，也更省。
5. **回谁**：回观众就 @ 对方；回主播不 @。
6. **收费**：免费，不扣任何人余额（限频已经给费用封了顶）。
7. **开关**：管理员指令 `/主动回复 开|关`，写进 commands.md 和提示词里的直播间设置。

### 判断的提示词（试过的版本）

> 你在帮抖音直播间的机器人「默认关闭」决定要不要主动说话。它平时只在被 @ 时回答，现在的人设是一只爱讲冷笑话的猫（观众可能叫它小咪、猫、机器人、小助手）。
>
> 看「新内容」（观众弹幕和主播说的话）里有没有一条是观众或主播在：
>
> - 直接对机器人说话（不一定 @，比如「默认关闭：…」「小咪…」）；
> - 评论、吐槽、夸、介绍机器人，哪怕没提名字，只用「它/他」指它（比如「怎么还有机器人」「可惜它也不能发表情包」「不接梗」，主播说「你可以跟他说话」「给它开个会员」）；要结合上下文判断「它/他」指的是谁；
> - 接机器人刚才那句回复的话。
>
> 有就选最值得回的那一条，reply=true。观众之间、观众对主播说的话（问主播问题、接主播的话）、主播跟观众聊别的都不算，reply=false。已经 @默认关闭 的不用管（会自动处理），reply=false。

人设里的叫法（「小咪」「猫」）应该从当前人设里来，不要写死。

## 试验结果（2026-10-18，房间 61843503134，16:03–16:15 的两段记录）

| 强度   | 判对 | 漏判                                                                     | 误判                            | 每次      |
| ------ | ---- | ------------------------------------------------------------------------ | ------------------------------- | --------- |
| low    | 6    | 3（「为难我」、「群聊小助手…你可以跟他说话」、「给你的机器人开个会员」） | 1（「会金玉良缘吗」是问主播的） | 约 4 秒   |
| medium | 9    | 1（「群聊小助手…」）；「开会员」那一窗选成了同窗的另一句                 | 0                               | 约 6.5 秒 |

- low 几次跑下来结果不稳定，所以用 medium。
- 「那你喜欢什么」「会金玉良缘吗」这种问主播的，medium 都没误判。
- 「可惜它也不能发表情包」「小咪不接梗」这种延续上文、只说「它」的，都判出来了。

### 费用

- 11 分钟判断了 27 次，每次约 1.5 万 token，大部分是 Codex 自带的系统提示词（一部分走缓存）。
- gpt-6-luna 价格：输入 $0.10、缓存输入 $0.01、输出 $0.50（每百万 token）。按 API 价格算每次约 $0.001，一小时约 $0.15。
- 用 ChatGPT 登录时走套餐额度，不另外扣钱。

### 一个要注意的问题

判出来的太多：这 11 分钟里有 9 条该回的，而且扎堆（16:10–16:15 大家一直在聊机器人）。都回就刷屏了，所以必须限频。冷却结束后，只看冷却期间最新的一批，不要补回旧的。

## 实现草图

- `app/follow-up.ts`：`FollowUp` 订阅直播间的弹幕和语音，攒 20 秒一批；`now` 和计时器通过构造参数传入，方便测试。
- 判断模型是一个 `AskClaude`（复用 `codexCli`，带 schema）；解析和校验放在 `core/` 里，写成纯函数。
- 判断要回时，向 `MentionAnswerer` 提交一个 Mention（`question` 就是那一条，`paid: 0`）。
- 指令 `/主动回复` 由 `FollowUp.commands()` 提供，在 `main.ts` 里接上。
