# room-feed

One Douyin live room's chat, gifts and likes, read from the room page in Chrome and sent to local clients (the site's overlays, the chat bot) over WebSocket. The streamer's guide is the site's `/room-feed-windows`; the endpoints are in the [repo README](../README.md#room-feed-live-room-events), and what they send and answer is typed in [`room-feed-protocol/`](../room-feed-protocol).

```sh
pnpm room-feed login             # from the repo root: log in to Douyin in a Chrome window
pnpm room-feed --room <房间号>    # serve that room on port 8757
```

Options: `--port <n>`, `--chrome <path to Chrome>` when it isn't found, `--headed` to see the room's Chrome window. The login is saved in `data/cookie.json` (not in git) and lasts about two months.

How it works: Chrome opens `live.douyin.com/<房间号>` with the saved login, so Douyin's own page does the signing and risk checks. `room-page.ts` watches the page's WebSocket frames over CDP; those that decode as Douyin push frames (`douyin/proto.ts`) are turned into events (`douyin/normalize.ts`) and sent to every client that asked for their type. Every other message (people entering, room notices, banners, a 直播间会员 bought…) is kept in `data/dropped/<房间号>/<YYYY-MM-DD>.jsonl` (not in git), one JSON line each: `ts`, `method`, `msgId`, `text` (the readable strings in it, found without its schema, so `grep 会员 data/dropped/*/*.jsonl` finds a message by what it says) and `payload` (its protobuf body, base64, for `protoc --decode_raw` or a schema once one is worked out). It's there to find what Douyin sends for things room-feed doesn't handle yet; nothing reads it. Chat is sent by typing into the page's chat box; when that fails (no box, a popup over it, the box not emptied by Enter) a screenshot of the page goes to `data/screenshots/` and its path ends the error the client gets. `room.ts` reopens the page when its push sockets all close, the page closes, or no push frame comes within a minute of opening it, waiting 5 s, 15 s, 30 s, then 60 s between tries in a row. It exits instead when there's nothing to wait for: the stream has ended, or hasn't started, as the page opens (`webcast/room/web/enter/` says status 4, or the page shows 直播已结束), so start it once the room is live; or a push message carries another room's id than the one the enter answer gave (Douyin's page moved to a room it recommends; the log has the page's address and a screenshot in `data/screenshots/`). Before it exits it sends every client an `__ended` frame (`reason`: `ended` or `wrongRoom`, `detail`: the reason in words), which `RoomFeedClient` reports as status `ended`, and closes their sockets cleanly. Exit code 0 on an ended stream, 1 on another room.

It started as a cut-down copy of [ymstar/dyhub](https://github.com/ymstar/dyhub), whose MIT licence is in [LICENSE](LICENSE): the protobuf schema, the message normaliser and the room-page code come from there.
